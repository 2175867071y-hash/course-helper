网课助手 1.6.48 使用说明

退出旧版，双击“网课助手-1.6.48.exe”。请沿用原来的 Windows 用户和数据目录，以便读取之前保存的 API 设置。

选择“通用课程（自动识别链接）”，粘贴章节网址，勾选“整门课连续学习”，点击“添加并开始”。识别到视频后，助手会尝试你设置的倍速；播放器不接受时，按实际速度继续。如果链接打开登录页或课程首页，先登录并进入具体章节。

如需双 AI 自动交卷，在“自动学习设置”中开启 AI 小测和“自动提交小测”，再到“交叉复核”勾选“启用交叉复核”，选择“豆包网页”。每批最多五题。两边收到同一组完整题图，有效答案逐题一致时，助手填写、核对页面选中状态并提交。自报置信度低于 0.85 也可以通过，返回 0 表示该模型无法作答，助手会暂停。有明确分歧时，当前课程任务结束，点“AI 结果”可以看到题号和双方的选择。

同节还有测验时先等测验加载。交卷确认后进入下一项；如果目录中的下一单元可识别，助手会先展开它。恢复同名课程时可继续上次识别到的视频、文档或测验网址。使用相同网址的多个活动由课程网站决定恢复位置。

交卷后若页面暂时空白，助手会等平台显示成功提示或逐题判分结果。等待超时会保留双方答案，方便你核对这次交卷。

以下为旧版本的故障说明。

本版修“提交成功、已确认交卷后仍不切下一节”。

日志里“已填写答案并提交小测 → 已确认交卷”后，程序反复报“课程页面仍在加载或切换”。原因是交卷后平台跳到结果页、题目区域消失，但程序在“已提交待确认”分支里仍先读取题目区域的任务标签和题目控件，这些读取在结果页上必然超时，于是卡住不切节。现在已提交待确认时先检测题目区域是否还在——不在就按“结果页＝已交卷”直接进入下一节，只有题目区域还在时才核对任务上下文。

本版修“两边结果一致却不填写提交”。

日志里豆包复核显示“5 道题全部一致”后，程序重新截图本地核对，随即报“AI 返回时题目内容已变化”。原因是 AI 请求耗时几十秒，期间页面滚动、浮层、重绘会改变截图字节，而旧的本地核对把截图字节也纳入比较，于是把纯视觉差异误判成“题目内容已变化”，不填写也不提交。现在本地核对只比较题目内容（题干、选项、填空）与页面指纹（忽略作答状态和纯样式，只反映题干/选项/材料结构），不再逐字节比较截图；真正的题目或材料变化仍会被拦截。

本版修“交卷成功后仍卡在结果页、不切下一节”。

日志里“已确认交卷”后 4 秒报“课程页面仍在加载或切换”。原因是交卷后平台跳到“我的答案”结果页，期间读取题目/任务上下文的调用会超时；这类超时此前直接转人工，把“结果页＝已交卷”的判断打断了。现在运行循环里遇到“页面仍在加载/切换”的读取超时，会在一段窗口内自动等待重试，页面稳定后继续走“结果页＝已交卷”并切下一节；只有持续加载超时才提示人工。

本版修“设置倍速后视频被播放器暂停、卡在开头要手动点继续”。

日志里设置 2 倍速后紧跟“播放器未保持所选 2 倍速，实际为 1 倍”，随后视频暂停。原因是超星播放器不接受倍速：检测到倍速被改成非 1 倍就把倍速重置回 1 倍并暂停视频；点一次“继续”后视频就以 1 倍速正常播放，说明暂停来自倍速检测而不是失焦。现在程序一旦发现播放器把所选倍速重置（即不接受倍速），就自动恢复播放并按实际 1 倍继续，不再打断；失焦时仍走后台焦点伪装，两者互不干扰。

本版修“视频播放一秒就自动暂停”和“一节视频+题目完成后不切下一章”。

一、视频播放一秒就自动暂停。点“开始”后焦点在软件窗口，课程浏览器失焦，超星用定时轮询 document.hasFocus() 检测到失焦就暂停视频；旧的后台播放兼容只拦事件、拦不住轮询，于是每次都要你手动切回浏览器再点播放。现在启动浏览器时会伪装焦点：只要页面（含嵌套 iframe）里有视频，document.hasFocus() 恒返回 true，超星不再判定失焦，视频在后台持续播放；登录、验证码等没有视频的页面保持真实焦点语义，不受影响。

二、一节视频+题目刷完不切下一章。交卷后页面会显示“我的答案／得分”结果页，截图指纹随之变化，程序把同一份卷子当成“新题目”，在切下一节时误判成“已切换到新活动”而不点下一节。现在：同一份已提交的试卷保持稳定身份；结果页被识别成文档时也记为已完成；切下一节时只有遇到“未完成的全新活动”才视为已切换，结果页或指纹变化会继续点下一节。

本版修“交卷后仍不切下一节”。
日志显示提交并确认交卷后 5 秒报“课程页面仍在加载或切换”，而页面其实已经是“我的答案”结果页——交卷成功，卡在读取。
原因：每轮的 guard 检查（登录、验证、弹窗）在结果页跳转时逐个读按钮文字，元素失效就抛超时，这个调用没有保护，整轮被打断，走不到“结果页=已交卷”的判断。
现在：读不到的控件直接跳过；guard 整体加入“页面仍在加载”的重试。

本版继续修“开头还是要手点播放”。
截图里视频已加载（0:00 / 15:31）但播放器没动，说明卡在“平台只认真实用户点击”这一层。现在启动顺序是：点播放控件 → 点击视频画面/控制栏播放键（Playwright 的点击走浏览器输入通道，事件是可信的，等同真人点击）→ 媒体接口 → 静音播放。前一步没反应才走下一步。
日志新增“浏览器已启动：自动播放策略=无需用户手势”，用来确认参数生效；如果开头仍要手点，说明是播放器自己的限制，日志能看到停在哪一步。

本版修“开头仍要手动点一次播放”和“做完题切不到下一节”。
一、开头要手点播放：浏览器默认要求“真实用户手势”才允许有声自动播放，脚本点击不算。现在助手启动浏览器时带 --autoplay-policy=no-user-gesture-required 解除该限制（只影响助手启动的浏览器），配合上一版的“点击控件 → 媒体接口 → 静音”三级兜底。这个改动要重启浏览器才生效：停止任务、重新添加课程。
二、做完题切不到下一节：日志里提交后 4 秒报“页面读取或操作失败（TimeoutError）”。本版把遗漏的读取路径也纳入处理：视频列表读取按“页面仍在加载”自动重试；运行循环遇到加载期超时会提示“课程页面仍在加载或切换，请稍后选择继续”，不再报“页面读取或操作失败”。

本版继续修“视频暂停后不会自己恢复”。
1.6.37 只是点一次播放控件、失败就记成“已尝试”，重试要等 10 秒；你点“继续”时往往还在 10 秒内，于是又被“已尝试启动本视频”挡住。
现在：播放控件点完没播，会继续用媒体接口启动；仍被浏览器拦住时，静音后再播一次（浏览器对静音媒体的自动播放限制最松），成功后保持静音；重试间隔从 10 秒缩短到 3 秒，允许三次；日志会写明是在哪一步启动的（点控件 / 媒体接口 / 静音）。三条路都不行才会提示你手动点一次播放。

本版修“一节两个任务都刷完却不切下一节”。
日志显示交卷确认成功后 4 秒报“页面读取或操作失败（TimeoutError）”：提交后平台正在跳转结果页，读取超时被当成致命错误，点继续也会重复失败。
现在：提交/切节期间的读取超时按“页面仍在加载”处理，自动重试三次，仍不行才提示稍后继续；交卷确认阶段遇超时跳过本轮、下一轮再确认；提交后页面若换成“结果页/返回页”，按已交卷处理并直接进入下一节。

本版修“视频已加载但暂停，点一次播放就放弃”。
日志里视频已经显示 0:01 / 16:37、播放器就绪，但程序点了一次播放控件没生效，就把这个视频记成“已尝试启动”，之后每次点继续都直接报“已尝试启动本视频”。
现在：点击后确认 1.5 秒内是否真的开始播放；有多个候选控件时逐个尝试；视频已加载但仍暂停时，间隔 10 秒允许再试一次，最多两次；正常播放时绝不重复点击；懒加载导致媒体地址变化时，新标识会继承“已尝试”的时间，不会被误当成新视频再点。

本版修两处：视频结束后又去点“视频”、视频一开始卡住要人工。
一、点错选项卡：超星“1 视频 / 2 章节测验”的 DOM 顺序可能是反的（章节测验在前）。旧版按 DOM 顺序取“当前项的下一个”，于是点回“视频”，页面切到下一节视频却停在 0.0 / 0.0 秒。现在按标签里的数字前缀排序后再取下一项。
二、视频一开始卡住：超星播放器是 preload=none，不点播放不取时长。现在启动视频时先发一次 preload=auto 与 load()（幂等，不会暂停），再点播放控件；15 秒后仍未加载会再请求一次，最多两次，然后才提示人工。

本版修交卷这一环的两个问题。
一、确认框里的“提交”点不到：超星“提示／确认提交？”弹窗的按钮是自定义 div（class="btn confirm"），既不是 button 也没有 onclick 属性，旧版识别不到。现在带 btn / button / confirm / submit 类的元素也纳入。同时还修了正文判断的错误——旧逻辑会把正文里的“提交”二字一并删掉，“确认提交？”变成“确认 ？”，于是被判成“不像提交确认”。
二、手动提交后不进入下一节：手动点提交后页面出现“提交成功”，题目指纹随之变化，程序把同一份卷子当成新题目，反复提示“本任务已尝试交卷，页面内容后来发生变化”。现在提交状态与成功基线都按“同一份试卷”记录，指纹变化后仍能认出已交卷并继续切换下一节。

本版让豆包不管回什么格式都能用。
豆包经常不按 JSON 要求，而回“1. 答案：D（安全体系）／2. 答案：B／汇总：1.D 2.B”。旧版只接受纯 JSON，这种回答会被当成无效，一直等到超时。
现在接收分三层：先按纯 JSON 校验；再从自然语言里按题号还原（分行、一行“1.D 2.B”、末尾“汇总”都支持，字母串 ABCD、判断题对/错、带解析的“答案：D（安全体系）”都能识别）；实在还原不出，就在同一对话里要求豆包整理一次 JSON，不重传题图；仍不行才暂停。
只有本批每道题都有唯一答案、且选项都在范围内才采用，不会猜。填空、拖拽题仍需要 JSON。

本版修复两点。
一、选项卡点错项：超星真实写法是 li 里再套 a 和 span，旧版把同一个条目算成两条，“下一个”就点成了当前项的另一个节点（日志显示“已点击：视频”）。现在同一文本归一到最外层节点。
二、新视频停在 0.0 / 0.0 秒：超星的播放按钮是播放器自己的覆盖层元素，不是可访问按钮。旧版找不到就退回原生 play()，被浏览器拦截。现在还会识别 .vjs-big-play-button、.prism-big-play-btn、class*=play-btn 等覆盖层。视频一直加载不出时，提示从 90 秒缩短到 45 秒。

本版修复：点了“章节测验”选项卡，页面却没有切换。
1.6.31 已经会点这一项，但超星的选项卡常把点击事件绑在内层或外层元素上，元素被遮挡时普通点击也会失败，于是提示“已点击…但内容未更新”。
现在每次切换会依次尝试四种点击方式：元素本身、脚本触发原生点击、内层元素、外层容器。
判定“已切换”也放宽为任一证据成立：选项卡高亮转移、页面地址变化、iframe 列表变化、出现“开始答题/进入测验”入口、可见文字明显变化、活动身份变化。等待时间从 20 秒延长到 30 秒。
如果该选项卡实际打开的是新标签页，助手不会在原页面反复点击，会提示你到新标签页作答。

本次修复两处切换失败。

一、视频看完不进入章节测验
超星把同一节的多个活动做成一排选项卡（“1 视频”“2 章节测验”）。旧版只会在整节结束后点“下一节”，不会点节内的下一个选项卡；而且视频看完但测验没做时，平台仍显示“任务点未完成”，旧版会直接判定失败。
现在视频或文档结束后，先点同节的下一个活动（章节测验、文档等），确认内容更新后再考虑下一节；任务点的延迟更新会等最多 10 秒再判断。本节没有活动选项卡时，才按原来的“下一节”按钮或目录切换。

二、做完题目切不到下一节
右侧目录里“章节标题”和“当前项”同时高亮时，旧版会认为有两个当前项，于是找不到下一节。现在只取最内层的高亮项。
点击目录后，只要页面地址变化就视为切换成功，不再因为新课还没加载完而误报。
切换过程中的页面异常会提示“请手动点右侧目录的下一项后选择继续，或用定位目录重新指定”，不再只显示“页面读取或操作失败”。

另外，“检测页面”的报告新增了本节的选项卡和目录下一项标题，便于核对页面结构。

1.6.30 的修复继续保留：豆包已经给出答案、助手却停在“等待独立复核答案”的问题。
旧版要求回答节点带 data-status=complete 之类属性，真实页面没有该属性，于是屏幕上已经显示的结构化 JSON 永远不被采用。现在按三条证据判断回答结束：页面上没有“停止生成”按钮、消息没有忙碌标记、同一段文本稳定不变；页面没有标准消息容器时也能直接从代码块读取 JSON。未写完的 JSON 无法通过本机结构校验，仍不会被误用。生成结束后出现的“复制”按钮也视为结束证据。

1.6.29 修复的四项问题继续保留。

一、豆包只输入不发送
缩略图渲染完成、没有上传进度标记也算上传完成；发送按钮改版后按 testid 变体和“发送”标签定位；找不到按钮或点击无效时按一次回车发送，并确认提示词已离开输入框。仍发不出去会明确报错，不会静默停在输入框。

二、两边一致后仍要重新问 AI
超星点击选项会把“已选择”写进 aria-label，旧版把这处变化当成题目页面变化，于是丢掉已复核答案、重新请求并再次等待。现在作答状态（aria-label 状态词、勾选图标、选中样式）不计入题目内容，一致后直接填写并交卷。题干、选项、材料或图片真的变化仍会暂停。

三、提交后不能自主翻页
“下一节”按钮没有固定 id 时，按“下一节、下一章节、下一讲”等文字查找唯一可用的链接或按钮。提交后平台任务点常延迟更新，现给 10 秒宽限再判断。切节使用刚完成的活动身份，页面已经显示提交成功也能继续。

四、截图不全
overflow: visible 的内容会画到边框外，旧版按边框截图会漏掉底部或右侧；现在按滚动尺寸扩大截图区域。材料容器里带“展开、播放”按钮时，不再整块材料被跳过。

1.6.28 的修复继续保留：多个窗口写入设置时不会互相覆盖 API 配置。如果另一个窗口改过 API 设置，请重新打开助手再保存。若此前的配置已丢失密钥，在“自动学习设置”中填入密钥，勾选“记住两组 API Key”并保存即可。

在“自动学习设置 → 交叉复核”中勾选“启用交叉复核”，选择“豆包网页”，保存后重新添加课程任务。升级保留旧的复核开关；若以前关闭了，请重新勾选。

豆包专用窗口与普通 Edge 的登录资料分开。第一次使用需要在助手打开的豆包专用窗口里自行登录，以后会沿用登录状态，不用配置豆包 API Key。助手不会修改 VPN 或系统代理；运行时仍需网络能访问豆包。

每组题先由原 AI 作答，再把同一批题目截图发给豆包新对话。豆包不会看到首轮答案，也不会收到 API Key。两边每题一致才继续填写，并按原有自动提交开关处理；答案分歧、超时或无有效回复时暂停。

答题处理暂停时，结果栏会显示各 AI 的答案、模型自报置信度和错误原因。点击课程列表上方“AI 结果”可打开更大的查看窗口。每门课分别保存当前题组结果，退出软件后不保留。

“原 API 多轮”模式继续保留：两轮独立回答，有分歧再做第三轮，每题至少两轮一致才填写。此模式可设置“API 复核图片模型”，留空就沿用原图片模型。两种复核方式都可能答错，模型自报置信度不等于正确率。

原有截图答题、听力转写、连续学习及自动提交设置继续使用。登录、验证码、个人自评和未适配的控件仍可能需要你处理。设置修改后停止并重新添加任务，单击“已处理，继续”不会更新运行中任务的配置。

题图会发送到配置的 AI 服务；启用豆包复核后也会发送到豆包账号下的新对话。音频发送到所配转写服务，转写结果随题目参与复核。API 调用可能产生费用，豆包对话和附件可能保存在服务端。

本机配置和进度位于 %LOCALAPPDATA%/CourseHelper，API Key 使用 Windows 当前用户加密。豆包登录资料位于该目录下的 doubao-review；不要分享整个数据目录。停止后当前同步请求仍可能需要等待返回。
