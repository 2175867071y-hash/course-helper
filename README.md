# 网课助手 1.6.48 ai复核试用版（Windows）

桌面版小测直接把题目和材料截图交给图片模型，不调用本机 OCR，也不提取题干或选项文字。长题通过滚动实际答题区完整截图，填写并核对控件状态后，滚动到底部提交按钮。网页结构仅用于绑定控件和在本机检查内容是否变化。

## 升级与使用

先停止旧版任务并退出，再双击 **网课助手-1.6.48.exe**。电脑需安装 Edge 或 Chrome。用原平台和课程名称重新添加任务可接续进度。

选择“通用课程（自动识别链接）”，粘贴具体章节网址，点击“添加并开始”。已登录且能识别课件时会直接开始播放、阅读或处理小测。课程首页和登录页会提示你打开具体章节。

在“自动学习设置”中开启 AI 小测、自动提交和交叉复核，复核方式选择“豆包网页”。两边收到相同的题目截图，每批最多五题。全部答案一致且页面核对通过时，助手填写并提交，即使一方自报置信度低于 0.85。置信度为 0 表示该模型无法作答，助手会暂停。两边给出不同答案时，当前课程任务结束，可在“AI 结果”逐题查看双方答案。

视频结束后先处理本节的其他活动。目录中下一单元带有可识别的展开按钮时，助手展开单元并进入第一项。下次用同名课程恢复时，助手优先打开最近识别到的课件网址；同一网址内的具体位置由平台恢复。

提交后，助手会等待本次测验的成功提示，或核对结果页是否已给每道题判分。表单暂时消失时会继续等待，超时后保留本组结果供检查。

## 历史版本

1.6.47 修“提交成功、已确认交卷后仍不切下一节”。

日志：`已填写答案并提交小测 → 已确认交卷` 后，程序反复报 `课程页面仍在加载或切换`。原因是交卷后平台跳到结果页、题目区域消失，但程序在“已提交待确认”分支里仍先读取题目区域的任务标签和题目控件，这些读取在结果页上必然超时，于是卡住不切节。现在：已提交待确认时先检测题目区域是否还在——不在就按“结果页＝已交卷”直接进入下一节，只有题目区域还在时才核对任务上下文。

1.6.46 修“两边结果一致却不填写提交”。

日志：豆包复核显示“5 道题全部一致”后，程序重新截图本地核对，随即报“AI 返回时题目内容已变化”。原因是 AI 请求耗时几十秒，期间页面滚动、浮层、重绘会改变截图字节，而旧的本地核对把截图字节也纳入比较，于是把纯视觉差异误判成“题目内容已变化”，不填写也不提交。现在：本地核对只比较题目内容（题干、选项、填空）与页面指纹（忽略作答状态和纯样式，只反映题干/选项/材料结构），不再逐字节比较截图；真正的题目或材料变化仍会被拦截。

1.6.45 修“交卷成功后仍卡在结果页、不切下一节”。

日志：`已确认交卷` 后 4 秒报 `课程页面仍在加载或切换`。原因是交卷后平台跳到“我的答案”结果页，期间读取题目/任务上下文的调用会超时；这类超时此前直接转人工，把“结果页＝已交卷”的判断打断了。现在：运行循环里遇到“页面仍在加载/切换”的读取超时，会在一段窗口内自动等待重试，页面稳定后继续走“结果页＝已交卷”并切下一节；只有持续加载超时才提示人工。

1.6.44 修“设置倍速后视频被播放器暂停、卡在开头要手动点继续”。

日志：设置 2 倍速后紧跟“播放器未保持所选 2 倍速，实际为 1 倍”，随后视频暂停。原因是超星播放器不接受倍速——检测到倍速被改成非 1 倍就把倍速重置回 1 倍并暂停视频；用户点一次“继续”后视频即以 1 倍速正常播放，说明暂停来自倍速检测而不是失焦。现在：程序一旦发现播放器把所选倍速重置（即不接受倍速），就自动恢复播放并按实际 1 倍继续，不再打断；失焦时仍走后台焦点伪装，两者互不干扰。

1.6.43 修“视频播放一秒就自动暂停”和“一节视频+题目完成后不切下一章”。

**视频播放一秒就自动暂停。** 点“开始”后焦点在软件窗口，课程浏览器失焦，超星用定时轮询 `document.hasFocus()` 检测到失焦就暂停视频；旧的后台播放兼容只拦事件、拦不住轮询，于是每次都要你手动切回浏览器再点播放。现在启动浏览器时会伪装焦点：只要页面（含嵌套 iframe）里有视频，`document.hasFocus()` 恒返回 true，超星不再判定失焦，视频在后台持续播放；登录、验证码等没有视频的页面保持真实焦点语义，不受影响。

**一节视频+题目刷完不切下一章。** 交卷后页面会显示“我的答案／得分”结果页，截图指纹随之变化，程序把同一份卷子当成“新题目”，在切下一节时误判成“已切换到新活动”而不点下一节。现在：同一份已提交的试卷保持稳定身份；结果页被识别成文档时也记为已完成；切下一节时只有遇到“未完成的全新活动”才视为已切换，结果页或指纹变化会继续点下一节。

1.6.42 修“交卷后仍不切下一节”。

日志：`23:28:08 提交 → 23:28:11 已确认交卷 → 23:28:16 课程页面仍在加载或切换`。截图里页面已经是“我的答案：ABC／错／对”的结果页，说明**交卷成功**，卡在读取。

原因：`guard()`（每轮检查登录、验证、弹窗）在结果页跳转时逐个读取按钮文本，元素失效就抛超时；这个调用在循环里没有保护，异常冒到外层，整轮被打断，因而走不到“结果页 = 已交卷”的判断。

修复：
- `guard()` 遇到读不到的控件直接跳过，不再抛错；
- `guard()` 整体加入“页面仍在加载”的重试；
- 顺带修掉 `videos()` 上重复的装饰器。

1.6.41 继续修“开头还是要手点播放”。

截图里视频已加载（0:00 / 15:31）但播放器没动，说明卡在“平台只认真实用户点击”这一层：脚本调用 `play()` 不算用户手势，浏览器策略开关也改变不了页面自己的判断。

现在启动顺序是：点播放控件 → **点击视频画面/控制栏播放键**（Playwright 的点击走浏览器输入通道，事件是可信的，等同真人点击）→ 媒体接口 → 静音播放。前一步没反应才走下一步，成功后立即停止，不会把正在播的视频点成暂停。

日志会加上“浏览器已启动：自动播放策略=无需用户手势”，用来确认新版浏览器参数确实生效；如果开头仍要手点，说明是播放器自己的限制，日志里能看到它停在哪一步。

1.6.40 修“开头仍要手动点一次播放”和“做完题切不到下一节”。

**开头要手点播放。** 原因是浏览器默认要求“真实用户手势”才允许有声自动播放，脚本点击不算。现在助手启动浏览器时带上 `--autoplay-policy=no-user-gesture-required`，解除这条限制（只影响助手自己启动的浏览器实例），配合上一版的“点击控件 → 媒体接口 → 静音”三级兜底。

**这个改动要重启浏览器才生效**：停止任务、重新添加课程即可。

**做完题切不到下一节。** 日志里提交后 4 秒报“页面读取或操作失败（TimeoutError）”。除了上一版已处理的确认与结果页，这一版补上遗漏的读取路径：视频列表读取也按“页面仍在加载”自动重试；运行循环里遇到加载期超时会提示“课程页面仍在加载或切换，请稍后选择继续”，不再报“页面读取或操作失败”。

1.6.39 继续修“视频暂停后不会自己恢复”。

1.6.37 只是点一次播放控件、失败就记成“已尝试”，而重试要等 10 秒；你点“继续”的那一刻往往还在 10 秒内，于是又被“已尝试启动本视频”挡住。

现在：
- 播放控件点完没播，会继续用媒体接口启动；仍被浏览器拦住时，**静音后再播一次**（浏览器对静音媒体的自动播放限制最松），成功后保持静音；
- 重试间隔从 10 秒缩短到 3 秒，允许三次；
- 日志会写明是在哪一步启动的（点控件 / 媒体接口 / 静音），便于判断是不是页面结构又变了。

如果三条路都不行，才会提示你手动点一次播放。

1.6.38 修“一节两个任务都刷完却不切下一节”。

日志显示交卷确认成功后 4 秒报“页面读取或操作失败（TimeoutError）”。原因是提交后平台正在跳转结果页，读取页面超时，而这类超时被当成致命错误，点继续也会重复失败。

改动：
- 提交/切节期间的读取超时按“页面仍在加载”处理，自动重试三次，仍不行才提示“稍后选择继续”，不再是致命错误；
- 交卷确认阶段遇到超时直接跳过本轮，下一轮再确认，不再中断整个流程；
- 提交后如果平台换成“结果页/返回页”（题目区域消失，或被识别成纯文字页），按“已交卷”处理并直接进入下一节，不再干等 30 秒。

1.6.37 修“视频已加载但暂停，点一次播放就放弃”。

日志里视频已经显示 0:01 / 16:37、播放器就绪，但程序点了一次播放控件没生效，就把这个视频记成“已尝试启动”，之后每次点继续都直接报“已尝试启动本视频”。

现在：
- 点击后确认 1.5 秒内是否真的开始播放（时长出现或不再暂停）；
- 有多个候选控件时逐个尝试，点到真正生效的那个为止；
- 视频已加载但仍暂停时，间隔 10 秒允许再试一次，最多两次；正常播放时绝不重复点击（避免把视频点成暂停）；
- 懒加载导致媒体地址变化产生的新标识，也会同步继承“已尝试”的时间，不会被误当成新视频再点。

1.6.36 修“视频结束后还去点视频”和“视频一开始卡住要人工”。

**点错选项卡。** 超星把“1 视频 / 2 章节测验”渲染出来后，DOM 顺序可能是反的（章节测验在前、视频在后）。旧版按 DOM 顺序取“当前项的下一个”，于是点回“视频”，页面切到下一节视频却停在 0.0 / 0.0 秒，日志显示“已点击：视频”。现在按标签里的数字前缀排序后再取下一项。

**视频一开始卡住。** 超星播放器是 `preload=none`，不点播放不取时长。现在每次启动视频会先发一次 `preload='auto'` 与 `load()`（幂等，不会暂停），再点播放控件；如果 15 秒后仍未加载，会再请求一次加载，最多两次，然后才提示人工。

1.6.35 修交卷这一环的两个问题。

**确认框里的“提交”点不到。** 超星那个“提示／确认提交？”弹窗的按钮是自定义 `div`（`class="btn confirm"`），既不是 `<button>` 也没有 `onclick` 属性，旧的按钮识别找不到它。现在把带 `btn / button / confirm / submit` 类的元素也纳入。

同时修了判断正文时的一个错误：旧逻辑会把正文里的“提交”二字一起删掉，“确认提交？”变成“确认 ？”，于是被判定为“不像提交确认”。现在改为克隆 DOM、删掉按钮元素再取文本。

**手动提交后不进入下一节。** 你手动点提交后页面出现“提交成功”，页面指纹随之改变，程序把同一份卷子当成“新题目”，于是反复提示“本任务已尝试交卷，页面内容后来发生变化”。现在提交状态和成功基线都按“同一份试卷”记录，指纹变化后仍能认出已交卷并继续切下一节。

1.6.34 让豆包不管回什么格式都能用。

豆包经常不按 JSON 要求，而回“1. 答案：D（安全体系）／2. 答案：B／汇总：1.D 2.B”。旧版只接受纯 JSON，这种回答会被当成无效，一直等到超时。

现在接收分三层：

1. 纯 JSON（含代码块）→ 直接校验；
2. 自然语言按题号还原：支持分行写、一行写“1.D 2.B”、末尾“汇总”，题号从 1 或 0 开始都能对齐；字母串（ABCD）、判断题“对/错”、带解析的“答案：D（安全体系）”都能识别；
3. 实在还原不出（缺题号、同题两个不同答案、选项越界）→ 在同一对话里要求豆包整理一次 JSON，不重传题图；仍不行才暂停。

只有“本批每道题都有唯一答案、且选项都在范围内”时才采用，不会猜。填空、拖拽题仍需要 JSON；判断题只回“对/错”而页面没有字母时也会要求整理，避免答反。

1.6.33 修两个问题。

**选项卡点错项。** 超星的真实写法是 `li` 里再套 `a` 和 `span`，1.6.32 会把同一个条目算成两条，于是“下一个”变成了“当前项的另一个节点”，日志显示“已点击：视频”。现在同一文本归一到最外层节点，高亮判定也包含内部元素。

**新视频停在 0.0 / 0.0 秒。** 超星的播放按钮不是可访问按钮，而是播放器自己的覆盖层元素，旧版只认 `播放/Play` 无障碍名称，找不到就退回原生 `play()`，被自动播放策略拦下。现在还会识别 `.vjs-big-play-button`、`.prism-big-play-btn`、`class*=play-btn` 等覆盖层（一次查询去重，仍要求唯一）。视频一直加载不出时，提示时间从 90 秒缩短到 45 秒，不必空等。

1.6.32 继续修“视频看完不进入章节测验”。1.6.31 会点该选项卡，但超星的选项卡常把点击事件绑在内层或外层元素上，被遮挡时普通点击也会失败，于是日志显示“已点击…但内容未更新”。

现在点一次会依次尝试四种方式：元素本身、脚本触发原生点击、内层元素、外层容器。判定切换成功也放宽为任一证据成立：选项卡高亮转移、页面地址变化、iframe 列表变化、出现“开始答题/进入测验”入口、可见文字明显变化、活动身份变化。等待从 20 秒延长到 30 秒。

如果该选项卡实际打开的是新标签页，助手不会在原页面反复点击，而是提示“本节的下一个活动在新标签页中打开，请到新标签页作答”。

1.6.31 修复了两处切换失败。

**视频看完不进入章节测验。** 超星把同一节的多个活动做成一排选项卡（`1 视频` / `2 章节测验`），旧版只会在整节结束后点“下一节”，不会点节内的下一个选项卡；如果视频看完但测验没做，平台仍显示“任务点未完成”，还会直接判定失败。现在视频或文档结束后先点同节的下一项（章节测验、文档等），确认内容更新后再考虑下一节；任务点的延迟更新也会等最多 10 秒再判断。

**做完题目切不到下一节。** 目录里“章节标题”和“当前项”同时高亮时，旧版会认为有两个当前项，于是找不到下一节。现在只取最内层的高亮项。点击目录后只要页面地址变化就算切换成功，不再因为新课还没加载完而误报。切换过程中的页面异常现在会提示“请手动点右侧目录的下一项，或用定位目录重新指定”，不再只显示“页面读取或操作失败”。

“检测页面”的报告新增了本节的选项卡和目录下一项标题，便于核对页面结构。

1.6.30 修复豆包已给出答案、助手却停在“等待独立复核答案”的问题。旧版要求回答节点带 `data-status="complete"` 一类属性，真实页面没有该属性，于是已经显示的结构化 JSON 永远不被采用。现在改为按“页面上没有停止生成按钮、消息没有忙碌标记、文本稳定”判断回答结束；页面没有标准消息容器时也能直接从代码块读取。未写完的 JSON 无法通过本机校验，仍不会被误用。同时修正 1.6.29 中发送按钮定位的两处细节，并把“复制按钮”视为生成结束的证据。

1.6.29 修复了本次反馈的四个问题。

**豆包只输入不发送。** 旧版只在附件卡片带“上传完成”属性时才继续，真实页面没有该属性，于是每次都等到超时，题图留在输入框里没有发送。现在缩略图渲染完成、没有上传进度标记也算完成；发送按钮改版后按 testid 变体和“发送”标签定位，找不到按钮或点击无效时会按一次回车发送，并确认提示词确实离开输入框，否则明确报错，不会静默停在输入框。

**两边答案一致后又要重新问一次 AI。** 超星点击选项会把“已选择”写进 `aria-label`，旧版把这处变化当成“题目页面已变化”，于是丢弃已复核答案、重新请求并再次等待。现在 `aria-label` 的作答状态词、勾选图标和选中样式不计入题目内容，一致后直接填写并交卷。真正的题干、选项、材料或图片变化仍会暂停。

**截图不全。** `overflow: visible` 的内容会画到边框外，旧版按边框截图，底部或右侧会被漏掉；现在按滚动尺寸扩大截图区域。材料容器里带“展开/播放”按钮时，也不再整块材料被跳过。

## 交叉复核

复核方式默认是 **豆包网页**；升级会保留已有的复核开关。如果原先关闭了复核，需要重新勾选。豆包不需要另填 API Key，首次使用专用浏览器窗口时需自行登录；后续沿用登录状态。助手不会修改系统 VPN 或代理，网络需能访问豆包。

每批使用新的豆包对话，助手确认 PNG 附件上传完成后发送题目。网页结束生成后，助手核对回复中的请求编号和题号。上传超时、回复缺题或模型明确表示无法作答时，助手会暂停并显示原因。两边给出的有效答案有分歧时，助手会结束当前课程任务。

每批最多 8 张图片，这是本程序的限制。只在完整题目之间分批，不裁剪或遗漏材料；单题超过限制、或共享限用词库题组无法完整发送时暂停。多门课共用豆包专用配置，排队复核，避免同时上传到同一个会话。各课程仍保留独立的进度和暂停结果。

**原 API 多轮** 保留 1.6.18 的方式：先独立作答两轮，有分歧再做第三轮，每题至少两轮一致才填写。此模式的 **API 复核图片模型** 留空时沿用原图片模型，也可填写同一接口和密钥可用的另一图片模型。原模型和复核模型都会显示在结果栏。

每轮使用相同题图和材料，不传入前轮答案。多选比较完整选项集合；填空文字、词库来源和拖拽对应关系也须一致。听力每段只转写一次，各轮共享转写结果。本版仍不调用 OCR 或提取题干、选项正文。

复核会增加等待时间和服务调用。两个 AI 一致仍可能同时答错，模型自报置信度也不等于实际正确率。本地测试只验证程序流程，尚未测得真实课程正确率。

停止任务需等待当前同步操作返回，返回后不再请求下一段转写或下一轮答案。修改设置后停止并重新添加课程任务，新设置才会生效。

## 自动提交与继续学习

进入课程并开始任务后，程序依次处理已适配的视频、文档和小测。小测截图交给 AI 后，程序填写并核对答案，再滚动到提交按钮。1.6.11 增加了交卷二次确认：本次提交触发的浏览器确认框或已识别网页弹窗，可自动确认；课件父页面中的确认框也会检查。看到本次提交成功的页面结果后，继续当前视频或进入下一节。

提交和确认按钮各只点击一次。若平台提示漏答、弹窗无法识别，或提交后 30 秒仍未确认成功，程序会暂停并显示原因。登录、验证码、个人自评和未适配题型仍可能需要本人处理，不能保证任意网站都能全程自动完成。

## 图片模型与听力

**图片模型是本版桌面答题所需配置。** 它和原来的文字服务共用 AI base URL 与 API Key。旧版文字模型字段保留配置兼容，本版截图答题使用图片模型。

DeepSeek 官方地址 `https://api.deepseek.com` 的图片模型留空时，程序使用 `deepseek-flash`，依据 [DeepSeek 图片输入文档](https://api-docs.deepseek.com/guides/vision/)。代理或其他服务需填写实际支持图片输入和 JSON 输出的模型；不能仅凭名称判断账户或代理已支持。模型不可用时暂停，不退回 OCR。

本版会拦截误填的 DeepSeek 官网、聊天页和控制台地址，并提示使用 API 地址。接口失败时显示具体 HTTP 状态码：401 检查密钥，402 检查余额，400/422 检查模型和参数，429 检查请求频率或额度，5xx 可稍后重试。只有 3xx 提示重定向，程序仍不会将密钥转发至重定向地址。日志不显示服务返回的原文或密钥。

听力在 **听力转写** 页配置独立服务、模型和密钥，需兼容 `/audio/transcriptions` 接口并返回含 `text` 的 JSON。程序读取完整音频并转写，再把转写结果与截图一起交给图片模型。另一服务的密钥不会自动复用。分片流、受限音频、视频内听力、语调辨识和本人跟读录音尚不支持。

## 目录与视频

保留整门课连续学习、多平台任务和后台播放兼容设置。已知平台使用对应适配，其他 HTTPS 课程链接尝试通用识别。视频自然结束后尝试进入下一活动；平台完成状态仍需以课程页面为准。

1.6.12 在 **自动学习设置 → 视频倍速** 中增加速度选择，可选 1、1.25、1.5、2、3、4 倍，初始值为 2 倍。保存后重新添加任务即可生效；每门已启动课程保留自己的速度设置。即使播放器没有倍速菜单，程序也会尝试设置标准视频播放速度。它使用浏览器的 [playbackRate 属性](https://html.spec.whatwg.org/multipage/media.html#dom-media-playbackrate)。

新视频加载后会应用所选速度，运行状态显示实际倍速。若播放器拒绝设置或自行恢复原速，日志会说明实际值，程序按该值继续观察，不反复强制覆盖。倍速只改变媒体播放速度；平台可能限制倍速或按实际观看时间计进度，不能保证任务完成时间同步缩短。若课程未计入进度，可改回 1 倍后重新启动任务。

无法自动定位目录时，在助手提示中选择定位目录，在本任务浏览器内依次点当前项和紧接着的下一项，记录完成后回助手继续。目录高亮变化但正文未更新时，程序会暂停。未知模板仍可能需要手动处理。

后台兼容不保证所有课程都能后台播放。运行时不要关闭浏览器，电脑需保持唤醒并联网；后台运行仍使用 CPU、内存和网络。

## 数据与费用

题目和材料截图发送至配置的 AI 服务；启用豆包网页复核后，同一批截图和材料也会发送到豆包账号下的新对话；音频发送至独立转写服务，转写结果再交给图片模型。调用可能产生对应服务费用。截图和媒体在内存处理，不写入进度记录。普通账户区域与导航栏排除在公共材料外；无法确认归属的通用页面只采明确标记的材料。

图形版数据保存在 `%LOCALAPPDATA%/CourseHelper`。`settings.json` 保存设置，密钥使用 Windows 当前用户加密；`progress.sqlite3` 保存视频观察记录。各任务的登录资料和日志位于 `tasks/<任务标识哈希>/`。豆包专用浏览器登录资料位于 `doubao-review/profile-msedge` 或 `profile-chrome`，对话和附件还可能保存在豆包服务端。更换 Windows 账户或电脑后不能直接解密原密钥。不要分享整个数据目录。

停止任务需要等当前同步操作返回。截图请求的单次网络等待时间为 120 秒，纯文字请求和语音转写为 30 秒。整卷处理包括截图、网络传输、生成回答和复核，可能超过这些时间。
